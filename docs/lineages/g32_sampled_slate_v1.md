# g32_sampled_slate_v1 — matched 32-task message-passing test

**Status:** `CLOSED` (2026-09-23) — **NO-GO** on the registered bipartite-message-passing bar. Registered before training and frozen before live outcomes.

**Question.** Does edge-aware bipartite message passing improve 32-task placement beyond a separately trained peer-only GNN and MP-OFF model when all three see the same data, features, objective, and serving budget? The [parent selector gate](gnn_proposal_selector_v1.md) established that an old GNN checkpoint contributes a useful candidate plan, but post-hoc lesions did not attribute that gain to message passing. Its ten-task training also differed from this 32-task live seat.

**Outcome.** The matched full GNN is slower than peer-only on **all eight** fresh topologies as a direct proposal and on **seven of eight** in the equal-size portfolio. Median full-model gains are **−1.691% direct** and **−1.866% portfolio** versus peer-only, and **−1.079% direct** and **−2.182% portfolio** versus MP-OFF. Every registered architecture bar fails for the **epoch-zero checkpoints selected by the sampled-sidecar validation rule**. A later exact-simulator validation read found that this rule penalized decoded final-epoch plans absent from the 16-plan slate and selected final weights for all three arms; the fresh [exact-selection successor](g32_exact_val_selection_v1.md) tests those weights. The original live verdict stands for its frozen checkpoints. The old checkpoint's [proposal-portfolio PASS](gnn_proposal_selector_v1.md) still stands as a complementary-proposal result, without graph-specific attribution.

**Artifacts.** The [training bundle](g32_sampled_slate_v1/training_artifacts_2026-09-23.tar.gz) preserves the complete v2 corpus and cache, all three checkpoints with sidecars, and offline Weights & Biases runs; SHA-256 `cef0028576f9cfe97ebafdcc5fb6e4e2c6a5bd49fb496191461a54ca3877879b`.

The full arm enables bipartite platform-edge message passing with nonzero edge attributes; peer-only disables that stage; MP-OFF disables all message passing. ## 2026-09-23 — implementation correction before checkpoint evidence

The first 16-plan corpus and cache did not cover every task–candidate edge in a group's sampled plans. The `partial_state_edge_attr` lookup raised `KeyError` during training, before any checkpoint evidence existed. The [generator](../../scripts_cosim/important/generate_sampled_slate_snapshots.py) now adds deterministic candidate-covering rows within the same 16-plan limit and checks coverage before writing a dataset. This is a data-contract repair, not a model result. Regeneration produced **128 graphs**, **2,048 scored plans**, and **4,096/4,096 task labels** in the v2 cache, with **197.47** task–candidate edges per graph on average. The [v2 topology split](../../experiments/g32_sampled_slate_v1_split_v2.json) retains **96/16/16** train/validation/test graphs and has SHA-256 `b151885a3096a1478d721ab2a3bcceb538f154274d276f5d061dfc85c16e4065`.

For 32-task groups, cache generation requires `DAG_PRIMARY_ALPHA_KEY=inf`; the initial primary alpha of `2.0` could not accommodate this group size. All three [training configs](../../experiments/g32_sampled_slate_v1_gnn.yaml) select `NEAR_RTT_TOP_K=1` because the trainer's top-five diagnostic would enumerate up to `5^32` plans; this changes that diagnostic, not the masked topology checkpoint-selection metric. Online Weights & Biases access and local socket access were unavailable in this workspace, so training logged to Weights & Biases offline with scratch files under `/tmp/g32train`.

## 2026-09-23 — validation read and checkpoint rule before the sealed gate

All three epoch-zero checkpoints decode the local-greedy slate row **0** on all **16** validation groups. Their `val/regret_masked_topo` is consequently the same **63.659547 s**; row 0 wins **7/16** sampled slates. The decoded plans match **65.04%** of task labels and map to a scored slate row in **100%** of groups. Cross-entropy is falling during the observed epochs, while decoded validation regret remains flat. The validation `base_load` field is `none`, so this flat result is not explained by a train/validation `base_load` parity mismatch. These are interim validation observations, not final training or test results.

Before opening any held-out test or live-gate outcome, apply this **identical validation-only selection rule** to each architecture. Compare the trainer-served checkpoint with its saved final-epoch checkpoint on the same 16 validation groups; choose the one with lower `val/regret_masked_topo`, breaking an exact regret tie with lower validation cross-entropy. If the epoch-zero served checkpoint wins both comparisons, serve epoch zero. Intermediate epoch weights are not saved, so this is explicitly a two-candidate selection, not a search over every epoch. Freeze the selected checkpoint and sidecar hashes before the live gate. Neither held-out test nor live outcomes may choose the checkpoint.

The lineage ends with a **fresh live gate regardless of the offline read**. Before opening outcomes, use coverage-only preflight on topology seeds starting at **9701**, take the first **eight** eligible seeds, and freeze their exact IDs, workload, runner/code hashes, checkpoint and sidecar hashes, and serving settings in this node. On each topology, run the three newly trained direct policies and the matched hand policy with the same six-pass coordinate-descent and exchange-scale-4 budget. Also run three equal-size portfolios: the frozen old MP-OFF and hand proposals plus **one** newly trained proposal from the full, peer-only, or MP-OFF arm, respectively, under the same deterministic selector. Each arm must complete the same fixed-replica, peer-enabled 160-group, 5,120-task workload; audit manifests, task/group counts, peer metrics, model contracts, code provenance, and inference time. The independent paired unit is the topology.

The primary metric is mean elapsed seconds per task within each topology. For a control, gain is `(control − full) / control × 100`; a tie is not positive. A **bipartite-specific PASS** requires **all** of these pre-registered bars: the full direct policy has at least **2% median** gain over *each* of peer-only and MP-OFF direct policies and a positive gain on at least **7/8** topologies against *each*; the full portfolio has at least **2% median** gain over *each* matched peer-only and MP-OFF portfolio and a positive gain on at least **7/8** topologies against *each*. Report hand comparisons separately; superiority to hand is not inferred from these architecture bars. Any failed bar is **NO-GO** for a bipartite-message-passing win in this seat, even if offline accuracy or one selector comparison is favorable. An invalid audit is repaired and rerun under the frozen protocol, never counted as a pass.

## 2026-09-23 — sealed-gate freeze

All three matched runs stopped after **20 epochs** (epoch 19) because decoded validation regret had not improved since epoch 0. Applying the rule above selected each trainer-served **epoch-zero** checkpoint. On the 16 validation groups, each selected checkpoint has `val/regret_masked_topo = 63.659547 s`, **100%** slate mapping, and **65.04%** task-label accuracy. Final-epoch cross-entropy was lower but decoded regret was worse: full **479.084947 s** with **31.25%** mapping, peer-only **257.581232 s** with **62.5%** mapping, and MP-OFF **298.194761 s** with **56.25%** mapping. The validation choice was made before opening held-out test or sealed live outcomes. It also means this gate serves weights from epoch zero; any result is evidence about that validation-selected model, not about beneficial learning over 20 epochs.

Coverage-only preflight selected the first eight eligible fresh topology seeds: **9701, 9702, 9705, 9706, 9707, 9708, 9710, 9711**. Each will run the three direct learned arms, the hand direct control, and the three equal-size portfolios under the serving settings above. The [freeze manifest](g32_sampled_slate_v1/gate_freeze_2026-09-23.json) records SHA-256 and byte size for all eight topology configs, fixed 5,120-task workload, three selected checkpoints and sidecars, frozen old MP-OFF checkpoint and sidecar, training configurations and split, generator, direct/portfolio/hand launchers, the seven-arm orchestrator, both Python runners, and both audit scripts. The manifest and this paragraph were written before sealed live outcomes were opened.

The preregistered bipartite-specific bar required **≥2% median gain and ≥7/8 positive topologies against each of peer-only and MP-OFF in both direct and portfolio seats**. None of its four comparisons passes. The full model's direct hand comparison is split **4/8** and does not establish a hand-rule win. Median total inference time across 5,120 tasks was **5.065 s** for full direct versus **4.833 s** peer-only and **4.837 s** MP-OFF; for the three-proposal portfolios it was **10.955 s** full versus **10.597 s** peer-only and **10.606 s** MP-OFF. The elapsed-time conclusion is an objective result, not a timing-only failure.

The validation-selected checkpoints came from epoch **0** in all arms; final-epoch weights reduced cross-entropy but worsened decoded validation regret, as recorded in the freeze above. Therefore this result closes **this 16-plan sampled-slate CE recipe, validation rule, and fixed-replica 32-task seat**. It does not show that no bipartite GNN can win under a different decision target or environment. The [train-only selector-headroom read](g32_sampled_slate_v1/train_only_selector_headroom.json) gives **7.350% aggregate** gain for a perfect 16-slate selector but is uneven across topologies; a perfect selector of the three existing proposals has only **0.200% median topology** headroom. Those are exploratory training-topology diagnostics, not a post-hoc gate rescue. A successor should first show that a new target or proposal mechanism creates reliable graph-specific headroom on fresh topologies, then register its own matched live gate.

### 2026-09-23 — post-gate validation-metric correction

The masked-topology validation metric looked up each decoded plan in the **16-plan sampled slate** and assigned a penalty when it was absent. Final-epoch plans mapped to a row in only **31.25%** of full-GNN groups, **62.5%** of peer-only groups, and **56.25%** of MP-OFF groups, so the earlier statement that their decoded regret was worse meant **worse under this capped lookup**, not worse simulator RTT. A later exact simulation of all decoded epoch-zero/final plans on the same 16 validation groups found final total RTT **970.803 s full, 1,400.261 s peer-only, and 977.404 s MP-OFF**, versus **2,204.862 s** at epoch zero for each. The epoch-zero simulation reproduced the cached row-zero RTT in all 16 groups. This discovery does not change the frozen 56-run live result; it narrows that result to its epoch-zero checkpoint choice. The [registered exact-selection successor](g32_exact_val_selection_v1.md) freezes final checkpoints and a new topology-held-out live gate before opening its outcomes.
