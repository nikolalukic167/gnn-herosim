PER-ARRIVAL XGBOOST (REGIME B) — IMPLEMENTATION PLAN
====================================================

Status: NOT IMPLEMENTED (requires dedicated co-sim dataset generation)
Regime A (batch) files live under src/policy/tabular/ and src/notebooks/prepare_tabular_dataset.py

Goal
----
Train and evaluate an XGBoost edge ranker on the same per-wakeup control loop as
knative_network and herocache_network (no 2ms batch collection window).

Why @seq0-only extraction is insufficient as the final Regime B dataset
-----------------------------------------------------------------------
- Tasks are drawn from N-task burst co-sim parents (conditional distribution).
- Labels are batch-oracle step-0 (min combo RTT), not marginal per-task oracle.
- Mid-burst decision states (after prior placements in same burst) are underrepresented.

Use @seq0 extraction (prepare_tabular_dataset.py --regime single) only as a
bootstrap / sanity check until Phase 2 co-sim lands.

4. Compare vs knative_network / knative_network_ect / herocache_network on same workloads.
5. Document limitation: burst-conditional data + batch-oracle labels.

Deliverables:

Phase 2 — Dedicated single-task co-sim (required for paper-grade Regime B)
---------------------------------------------------------------------------
2.1 Dataset layout
  simulation_data/artifacts/run_queue_big/gnn_datasets_1task/
    <dataset_id>/
      optimal_result.json      # 1 task, marginal optimal placement + RTT
      placements/placements.jsonl   # optional: all feasible placements + RTT
      infrastructure.json      # or symlink / reuse parent infra snapshot
      workload slice metadata

2.2 Co-sim driver changes (scripts_cosim/)
  - New script: scripts_cosim/generate_single_task_datasets.py
  - Input: existing infra configs OR sampled snapshots from live sim SSC captures
  - For each snapshot S and single task T:
      * brute-force or hash all compatible (node, platform) placements
      * record exact co-sim RTT for that task alone (no co-arrivals in batch)
      * label = argmin RTT platform
  - Output SSC / optimal_result.json compatible with existing graph builder

2.3 Graph / tabular cache
  - New builder: src/notebooks/prepare_graphs_cache_single.py
      * 1 task per graph (n_tasks=1 always)
      * No seq_step / prefix logic needed
      * queue_snapshot = exogenous cluster backlog at arrival
  - Or skip PyG entirely: scripts_cosim/generate_single_task_datasets.py emits
    tabular parquet directly using shared feature builder

2.4 Shared feature builder (required for parity)
  - Extract from GNNScheduler._build_inference_graph into:
      src/policy/tabular/feature_builder.py
  - Used by: prepare_graphs_cache*, live schedulers, single-task co-sim exporter
  - Guarantees identical 22-d scaling (adaptive p90 queue norm, node_cold_replicas, etc.)

2.5 Training
  - prepare_tabular_dataset.py --regime single on new 1-task cache
  - train_ranker.py -> models/tabular/single_edge_ranker_v2.json
  - Group split by parent_dataset_id (snapshot id)

2.6 Live scheduler
  - XGBoostSingleScheduler:
      while True:
        task = yield tasks.get(filter)
        mutex -> build 22-d rows for compatible replicas -> argmax -> dispatch
  - NO batch_timeout, NO in-batch queue roll-forward dict (SimPy state is live)
  - Reuse knative_network replica filtering + autoscale paths

2.7 Evaluation matrix (Regime B row)
  Policy                    | Batching delay | ML
  --------------------------|----------------|----
  knative_network           | no             | no
  knative_network_ect       | no             | no
  herocache_network         | no             | no
  xgboost_single (Phase 2)  | no             | yes
